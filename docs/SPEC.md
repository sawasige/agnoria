## 0. 概要

| 項目 | 内容 |
|---|---|
| アプリ名 | **Agnoria**（アグノリア） |
| 由来 | ギリシャ語 Agnoia（無知）＋ ローマの女神 Agenoria（子どもに学ぶ力を授ける）。「無知から学び始める」の意 |
| 目的 | TOEIC 450→600点帯の学習者が、スキマ時間に **単語** と **Part5形式の文法** を4択ドリルで繰り返す |
| 対象 | まず開発者自身。あわよくば App Store 公開 |
| 対応OS | **[v1.1]** iOS / iPadOS 27 以上（iPhone は縦画面のみ、iPad は全方向）/ macOS 27 以上（ネイティブ SwiftUI の1ターゲット。Mac Catalyst は使わない） |
| 通信 | なし。全データをバンドル同梱。広告なし、課金なし、アカウントなし |
| 商標回避 | アプリ名・Bundle ID・画面内の固定文言に「TOEIC」を使わない。App Store 説明文で「TOEIC対策に」と触れる程度は可 |

### 既存アプリへの不満（＝設計の軸）
- 「わかる／わからない」の自己申告は、自信のない単語を判定できない → **必ず4択で正誤が出る**
- 分野を狙って繰り返したい → **分野タイルから10問セットを何度でも**

## 2. データ

### 2.1 バンドルJSON

`Agnoria/Resources/Data/` 配下に `grammar.json` / `words.json` を置く（synchronized folder なので Xcode に手で追加する必要はない）。起動時に SwiftData へ取り込む。

#### `grammar.json`（Part5 文法）
```json
{
  "id": "pos-001",
  "category": "品詞",
  "question": "The manager asked the team to submit their reports ______.",
  "choices": ["prompt", "promptly", "promptness", "prompted"],
  "answer": 1,
  "explanation": "動詞 submit を修飾するので副詞 promptly。-ly は副詞の目印。",
  "level": 500
}
```
- `answer` は `choices` のインデックス（0始まり）
- `category` は以下の5種（v1）: `品詞` / `前置詞・接続詞` / `語彙` / `時制・態` / `代名詞・関係詞`
- `level` は 450 / 500 / 550 / 600 の4段階（目安スコア帯）

#### `words.json`（単語）
```json
{
  "id": "w-0001",
  "word": "invoice",
  "pos": "名詞",
  "meaning": "請求書",
  "example": "Please pay the invoice within 30 days.",
  "example_ja": "30日以内に請求書をお支払いください。",
  "distractors": ["領収書", "見積書", "契約書"],
  "category": "ビジネス一般",
  "level": 450
}
```
- `distractors` は **意味が近い日本語の誤答3つ**（人手で作成。ランダム語は不可）
- `category` は以下の5種（v1）: `ビジネス一般` / `人事・採用` / `会議・連絡` / `店舗・顧客` / `混同しやすい語`
- `pos` は `名詞` / `動詞` / `形容詞` / `副詞` / `前置詞` / `接続詞`

#### 取り込みルール
- `id` を主キーに upsert。JSON側で問題文を修正したら次回起動時に反映される
- 学習履歴（正誤・ブックマーク）は `id` に紐づくので、問題を更新しても履歴は消えない
- JSON に存在しなくなった `id` は削除しない（履歴保護）。`isArchived = true` にして出題対象から外す。再び JSON に現れたら `isArchived = false` に戻す
- **[v1.1]** 取り込みは毎起動時にバックグラウンドで行うが、2ファイルの SHA-256 が前回取り込み時と同じならスキップする（UserDefaults に保存）

### 2.2 SwiftData モデル

```
GrammarQuestion
  id: String (unique)
  category, question, choices: [String], answer: Int, explanation, level: Int
  isArchived: Bool

Word
  id: String (unique)
  word, pos, meaning, example, exampleJa, distractors: [String], category, level: Int
  isArchived: Bool

ItemProgress              // [v1.1] リレーションではなく itemID で紐づける独立レコード
  itemID: String (unique) // GrammarQuestion.id または Word.id
  recentResults: [Bool]   // 直近3回の正誤。古い順。最大3件
  totalCorrect: Int
  totalAnswered: Int
  isBookmarked: Bool
  lastAnsweredAt: Date?

StudySession              // 1セット＝10問の記録。完走したときだけ保存
  id: UUID
  startedAt, finishedAt: Date
  mode: String            // "grammar" / "word"
  category: String?       // nil = ミックス
  questionFormat: String? // 単語のとき: "meaning" / "cloze" / "jaToEn"
  results: [SessionResult]  // [v1.1] Codable 構造体の配列として埋め込む

SessionResult
  itemID: String
  isCorrect: Bool
  chosenIndex: Int
  elapsedMs: Int
```

## 3. 出題ロジック

### 3.1 単語の出題形式（1語から3形式を自動生成）

| 形式 | 問題 | 選択肢 | 誤答の出どころ |
|---|---|---|---|
| `meaning` 意味を選ぶ | `invoice` | 請求書 / 領収書 / 見積書 / 契約書 | `distractors` |
| `cloze` 例文穴埋め | `Please pay the ______ within 30 days.` | invoice / receipt / estimate / contract | 同じ `pos`・同じ `level` の他の単語から3語をランダム抽出 |
| `jaToEn` 日→英 | 請求書 | invoice / receipt / estimate / contract | 同上 |

- `cloze` は `example` 中の `word` を `______` に置換。**[v1.1]** 完全一致（大文字小文字無視）→ 規則的な語尾変化（-s/-es/-ed/-d/-ing/-ly、-e 脱落、-y→-ies、子音重ね）の順に探す。単純な先頭一致はしない（`in` が `invoice` に化けるため）。見つからなければその語は `meaning` 形式で出す
- 誤答抽出は **[v1.1]** 同 `pos`・同 `level` → 同 `pos` → 全単語 の順に条件を緩める。自分自身・同じ綴り・同じ `meaning` の語は除く

### 3.2 セット生成（10問）

```
入力: mode（nil = おまかせ [v1.2]）, category（nilならミックス）, format（単語のみ）
1. 対象 = isArchived == false かつ mode 一致（おまかせなら単語・文法の両方）かつ category 一致（ミックスなら全件）
2. 優先度スコアを付ける（d = 最後に答えてからの経過日数 / 14 を 0〜1 に丸めたもの [v1.2]）
     未回答:                    3
     直近3回に不正解あり:       2 + (不正解の数)
     直近3回すべて正解:         0.3 + 1.2 × d   ← 「卒業」。除外はしない。2週間放置で 1.5 まで戻る
     それ以外:                  1   + 0.5 × d
     [v1.4] 過去に習得済み（masteredAt あり）の問題は、直近が正解なら「卒業」の重み、直近が不正解なら「不正解あり」の重み
3. スコアを重みにして重み付きランダムで10件抽出（重複なし）
4. 各問の選択肢の並びをシャッフル。正解のインデックスを記録
```

- **[v1.2]** おまかせ（`QuizConfig.auto`）は単語・文法の全分野を1つの候補群にして上の手順で抽出する。単語の形式は1問ごとにランダム。「何を勉強するか」をユーザーが選ばなくて済むのが目的。未回答が最優先、次に間違い、放置した卒業問題は時間とともに復習に回る
- **[v1.2]** 習得段階（`Mastery`）: 未学習（未回答）/ 苦手（直近3回に不正解）/ 学習中（それ以外）/ 習得（直近3回すべて正解）。優先度と同じ判定を4段階に写しただけで、ロジックは持たない。「復習待ち」= 習得後 7 日以上経過
- **[v1.4]** 一度習得した問題の扱い: はじめて3連続正解した日時を `ItemProgress.masteredAt` に残す。以後その問題は **直近の1回が正解なら習得**（3連続を待たない）、直近が不正解なら「学習中」（苦手には落とさない）で、次のセットに優先的に出る（重みは不正解と同じ）。復習で1回ミスしただけで未学習相当に落ちると、全体の習得率が 97〜99% で頭打ちになる（シミュレーションで確認）ため。更新前から習得していた問題には、起動時に最後の回答日時を `masteredAt` として補う（`AppModel.backfillMasteredAt`）
- 対象が10件未満なら、あるだけ出す（最低1件）
- 「間違えた問題だけ」モード: 直近3回に不正解を含むもののみ
- 「ブックマークだけ」モード: `isBookmarked == true` のみ

### 3.3 回答記録

- 回答時に `Progress.recentResults` に append、4件目以降は先頭を落とす
- `elapsedMs` は問題表示から回答タップまで
- Foundation Models で生成した類題（§5）は **記録しない**
- **[v1.1]** 途中離脱しても回答済みの `ItemProgress` はそのまま残す。`StudySession` だけ保存しない（連続日数には数えない）

### 3.4 ステージ **[v1.3]**

「何を勉強すべきか」をさらに絞るため、スコア帯を 450 → 500 → 550 → 600 の順に進む。

- **到達帯** `unlockedLevel`（UserDefaults、初期値 450）。出題対象は到達帯以下のレベル（おまかせも分野タイルも）
- **今の帯** = 到達帯以下で未クリアの最も低い帯。すべてクリア済みなら到達帯
- **クリア** = その帯の全問題（単語＋文法）のうち習得（直近3回すべて正解）が **80%** 以上
- セット完走時に到達帯がクリアされていれば次の帯を開く（最上位 600 なら何もしない）。結果画面で知らせる
- おまかせの重みは §3.2 のスコアに係数を掛ける: 今の帯 ×1、それ以外の到達済み帯 ×0.35（復習として少し混ざる）、未到達 ×0
- 下の帯の習得率が落ちれば「今の帯」はそこへ戻る（到達帯は下がらない）
- 設定で到達帯を手で変えられる（先に進む・戻る）。履歴リセットで 450 に戻る

## 4. 画面

### 4.1 ホーム **[v1.4]**
状態を見る **ダッシュボード**。学習の選択肢は置かず、入口は画面下の固定バーだけ（旧構成は §4.7 へ移動）。上から順に:
- **ヘッダー**: アイコンと同じ女神 Agenoria の立ち絵（`AgenoriaPortrait`、高さ 64pt）と「Agnoria」の見出し。ナビゲーションバーのタイトルは消す（`toolbar(removing: .title)`）
- **今の帯カード**: 今の帯（例「500 点帯の習得」）の習得率（%）を大きく、その帯の4段階の積み上げバー、「あと N 問の習得で 550 点帯へ」とその下に小さく **クリアまでの目安**「目安 約 40 セット・今のペースなら約 8 日」（`Pace.estimate`。1 セットあたりの習得数は直近 14 日の実績に既定値 1.8 問/セットを重み 10 セット分で混ぜたもの、1 日あたりセット数は直近 14 日、始めてそれに満たないなら始めた日からの平均。直近 14 日に学習がなければ「目安 約 N セット（1 セット 3〜4 分）」。クリア済みなら出さない。60 日以上は「約 N か月」）。右上に 4 帯のミニ表示（クリア済み ✓ 緑 / 今の帯 ● / 開いている ○ / 未到達 🔒）。タップで進捗画面（§4.6）
- **連続 / 今日**（半幅カード 2 枚）: 🔥 連続学習日数（今日まだやっていなければ「今日はまだ」をオレンジで強調）/ 今日の回答数と正解率（0 問なら「1 セット 10 問から」）
- **この2週間**: 直近 14 日の日別棒グラフ（§4.6 と同じ部品）。タップで進捗画面
- **復習カード**: 「復習待ち N ・ 苦手 N」（到達帯までの全件）と `間違えた N` / `ブックマーク N` の 2 ボタン（0 件は disabled。単語・文法の合算）。**4 つの数がすべて 0 なら表示しない**
- **下部固定バー**（`safeAreaInset`、クイズ画面の操作列と同じ作法）: `おまかせで10問`（主。サブテキストに「500 点帯: 苦手 N・未学習 N・復習 N」、全部習得済みなら「復習で定着させよう」。Mac では Return）と `分野`（副。§4.7 へ）
- 称号（§4.5）と全体の習得率はホームには出さない（進捗画面へ）

### 4.2 クイズ
- 進捗 `3 / 10`、現在の分野名
- 問題文。文法は英文、単語は形式に応じた表示（§3.1）
- 4択ボタン（縦並び）。タップで即確定

  - 正解: 選んだ選択肢を緑。不正解: 選んだものを赤、正解を緑

- **[v1.2]** 進捗は `3 / 10` の文字に加え、10個のドット（回答済みは正誤の色、現在の問題はアクセント色）
- 制限時間なし。途中離脱はセット破棄（確認ダイアログあり）
- 左上 `×` でホームへ

## 5. Foundation Models（任意機能・v1に含める）

対応端末（`SystemLanguageModel.default.availability == .available`）でのみ表示。

1. **解説の言い換え**（文法のみ **[v1.1]**）: 解説の下に `別の言い方で` ボタン。元の解説を渡して「ビジネス英語を学び始めた初中級（スコア帯450点前後）の日本語話者向けに、日本語で2文以内で言い換えて」と指示。結果は保存しない。**指示文にも商標名は入れない**（§10 の grep 条件のため）

生成に失敗・タイムアウト（5秒）したらボタンを静かに消す。エラー表示はしない。

## 6. 音声
- `AVSpeechSynthesizer`、`AVSpeechSynthesisVoice(language: "en-US")`
- 例文のみ読み上げ。単語単体の読み上げは v2
- **[v1.1]** マナーモード（サイレントスイッチ）に従う。`.ambient` カテゴリなので消音中は鳴らない。自動読み上げをデフォルト ON にしたため、意図せず音が出る経路を無くす。`AVAudioSession` は iOS のみなので `#if os(iOS)` で囲む
- **[v1.2]** 効果音は `Resources/Sounds/correct.caf` / `wrong.caf`（合成音。44.1kHz mono 16bit、ピーク -6 dBFS）を `AVAudioPlayer` でプリロードして鳴らす。セッション設定は読み上げと共有（`AudioSession`）なので、効果音もマナーモードに従う
- **[v1.4]** `AVAudioSession` の `setCategory` / `setActive` と `AVAudioPlayer` の `prepareToPlay` / `play` は内部で同期的にセッションを有効化し、メインスレッドで呼ぶと Xcode が「AVAudioSession Hang Risk」を報告する。`AudioSession` と `SoundEffects` は actor にして、これらをメインスレッド以外で実行する（View からは `SoundEffects.shared.play(_:)` を呼ぶだけで待たない）。シミュレータのログで、旧実装では 1 セット中に 5 件出ていた診断が 0 件になることを確認済み

## 7. 非機能
- ダークモード対応（標準コンポーネントに任せる。独自色は正誤の緑／赤と、習得段階の4色のみ **[v1.2]**）
- **[v1.2]** 見た目は Liquid Glass（iOS 27 / macOS 27 標準）。全画面に淡いメッシュグラデーション背景を敷き、カード・選択肢・操作列は `glassEffect`、主ボタンは `.glassProminent`、副ボタンは `.glass`。独自の描画はこれ以上しない（Reduce Transparency 時の不透明化は OS 任せ）
- Dynamic Type 対応。4択ボタンは2行まで折り返し可
- VoiceOver: 選択肢に `A〜D` のラベル。正誤結果を読み上げ
- 起動 → ホーム表示まで 1秒以内（JSON取り込みはバックグラウンドで、内容が変わったときのみ **[v1.1]**）
- **[v1.1]** Mac: 選択肢 `1`〜`4` キー、`次へ` Return、`×` Esc。最小ウィンドウ 480×640（**[v1.4]** ホームの下部固定バーもこの中に収まる）
- **[v1.1]** iPad / Mac: コンテンツ幅は最大 720pt で中央寄せ。ホームのタイルは幅に応じて列数が増える（1列あたり最小 160pt）。iPad は専用レイアウトを持たず、iPhone と同じ画面構成を広げて使う
- クラッシュ時に学習履歴が消えないこと（SwiftData のデフォルト設定で可）
- **[v1.4]** 女神 Agenoria の画像は `Assets.xcassets` の `AgenoriaPortrait`（アイコンと同じ絵、600px）と表情 4 枚 `AgenoriaJoy / Happy / Neutral / Sad`（ChatGPT 生成の 4 コマ画像を分割し、市松模様の背景を外周からの塗りつぶしで透明化。619px）。単一スケールの PNG
- **[v1.3]** アプリアイコンは `Agnoria/Agnoria.icon`（Icon Composer）。女神 Agenoria の胸像イラスト 1 レイヤー（月桂冠と手の上の若葉）に白〜淡いミントの背景。光沢・影・ダーク外観は Icon Composer 任せ

## 8. 問題データの作り方（開発者向け）

- **すべてオリジナル問題**。市販問題集・公式問題集・単語帳の例文・解説の転載、言い回しを変えただけの改変は不可
- 単語リスト自体（頻出語）は事実情報なので使ってよい。例文・和訳・誤答を自作する
- 初期目標: 文法 5分野 × 50問 = 250問、単語 5カテゴリ × 50語 = 250語。動いたら各100まで増やす
- 初期データ **[v1.1]**: `grammar.json`（文法30問。5分野×6問、自作）、`words.json`（単語50語。旧 `words_sample.json`）
- **[v1.3]** 単語 400（各スコア帯 100、各カテゴリ 80）、文法 200（各スコア帯 50、各分野 40）。既存の 80 問はそのまま残し、残りは Claude がスコア帯ごとに書いた（未レビュー）。単語の綴りは全体で一意。検証スクリプトでチェックした項目: 形式・id の重複・綴りの重複・穴埋めが作れること・誤答が意味と重複しないこと・正解位置の偏り・「TOEIC」不在
- 生成は Claude Code に任せてよいが、以下をチェック:
  - 正解が一意であること（他の選択肢でも文法的に成立しないか）
  - `distractors` が意味的に近いこと
  - `level` が 450〜600 の帯に収まっていること（難語・専門語は入れない）
