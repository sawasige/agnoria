## B. ロジックの穴

| # | 箇所 | 問題 | 決定 |
|---|---|---|---|
| B1 | §3.1 cloze | 「先頭一致で置換」だと、`in` が `invoice` の先頭に、`port` が `report` 内にマッチして誤置換する。 | 完全一致 → 規則変化（-s/-es/-ed/-ing/-ly、-e脱落、-y→-ies、子音重ね）のみ許可。語長3未満は活用形マッチ対象外。テストで `in`/`invoice` の非マッチを固定。 |
| B2 | §3.1 誤答抽出 | フォールバックは「level を外す」までしか無いが、サンプルでは **前置詞が1語**しかなく、同 pos で3語確保できない。 | 同 pos・同 level → 同 pos → 全体、の3段。さらに同じ `meaning`／同じ綴りの語は誤答から除外（正解が2つになる事故を防ぐ）。 |
| B3 | §3.1 cloze | 例文に `word` が見つからない語は「cloze 対象外」とあるが、その場合に何を出すか未定義。 | その語は `meaning` 形式にフォールバックして出題数を減らさない。 |
| B4 | §4.2 途中離脱 | 「セット破棄」とあるが、§3.3 は回答ごとに Progress を即時記録する。どちらを優先するか曖昧。 | 回答済みの Progress は残す（学習は無駄にならない）。`Session` だけ保存しない（連続日数には数えない）。離脱ダイアログにその旨を表示。 |
| B5 | §2.2 Progress | `GrammarQuestion` と `Word` の両方から 1:1 で `Progress` を持つと、SwiftData では Progress 側に2本の optional 逆参照が必要になり不自然。 | `ItemProgress` を独立モデルにし `itemID`（unique）で紐づける。問題の更新・アーカイブ・再登場で履歴が消えないことをテストで確認。`Progress` という名前は Foundation の `Progress` と衝突するため `ItemProgress` に。 |
| B6 | §2.2 Session.results | `SessionResult` をリレーションにする必要がない。 | Codable 構造体の配列として `StudySession` に埋め込む。 |
| B7 | §4.1 下部ボタン | 「間違えた問題」「ブックマーク」の件数が単語・文法どちらの集計か未定義。 | 現在選択中のセグメント（単語 or 文法）の件数。出題もそのモードのみ。 |
| B8 | §4.4 レベル絞り込み | 絞り込みで対象が0件になったときの挙動が未定義。 | タイルは `0件` で disabled。開始時に0件ならアラートで「レベルを広げるか別の分野を」と案内。 |
| B9 | §5 言い換え | 単語の「解説」は意味＋例文＋和訳で、言い換える対象が無い。 | 「別の言い方で」は文法の `explanation` にのみ表示。 |

## C. Mac 対応で追加したもの（仕様外・最小）

- 選択肢に `1`〜`4` キー、`次へ` に Return、`×` に Esc のキーボードショートカット。
- ウィンドウ最小サイズ 480×640、既定 560×820。
- ツールバー配置は `.cancellationAction` / `.primaryAction` を使い、iOS では左上 `×`・右上ボタン群として表示。
- App Sandbox を有効化（通信なしなので追加の entitlement は不要）。
- 1ウィンドウのアプリなので macOS では `WindowGroup` ではなく `Window` シーン（File > New Window が付かない）。最後のウィンドウを閉じたら終了。Edit（取り消し・ペーストボード）、View > ツールバー、Help の既定メニュー項目は外す。

## G. v1.2 の判断（2026-10-13）

ユーザー要望: 「勉強する項目を選ぶのが面倒で、何を勉強すべきか判断できない。網羅的かつ苦手を自動で」「正誤で音を鳴らしたい」「UI がダサい」。

| # | 判断 | 理由 |
|---|---|---|
| G1 | おまかせは **単語・文法を1つのセットに混ぜる** | 「網羅的」の最短。片方ずつにすると結局ユーザーがどちらかを選ぶことになる。分野タイルは残したので従来どおりの出題も可能 |
| G2 | 優先度に **経過日数** を足した（卒業 0.3→1.5、学習中 1→1.5、14日で上限） | 旧ロジックは卒業した問題がほぼ出なくなり、忘れても戻ってこない。間隔反復の簡易版。未回答・間違いは時間に依存しない |
| G3 | 習得段階は Priority の判定をそのまま4段階にしただけ | 可視化のために別の指標を増やすと、出題ロジックと画面の数字がずれる |
| G4 | `間違えた問題` / `ブックマーク` は **単語・文法の合算** | おまかせと同じ思想。v1.1 の「選択中セグメントのもの」から変更 |
| G5 | 効果音は **合成音**（Python の wave で生成し afconvert で CAF 化） | ライセンス不明の音源を持ち込まない。最初のやわらかいチャイムは不評で、3案（クイズ番組風 / ゲーム風 / 控えめ）を聞き比べて **クイズ番組風（ピンポーン / ブッブー）** に決定（2026-10-13）。差し替えは同名の CAF を置くだけ |
| G6 | 効果音の後に自動読み上げを **0.45 秒遅らせる** | 効果音と読み上げがかぶると両方聞き取れない。v1.1 で懸念していた「読み上げが早すぎる」も同時に解消 |
| G7 | UI は **Liquid Glass ネイティブ**（ユーザー選択。他案: ダーク固定 / フラット・ポップ） | OS 標準のスタイルなので手描きの装飾が最小で済み、ライト／ダーク両対応が自動。Xcode 既定から外れるビルド設定も不要 |
| G8 | 進捗画面は閲覧のみ。操作はホームに集約 | 「何をやるか」はおまかせボタン1つにしたいので、進捗画面から出題を始められるようにしない |
| G9 | `StudySession.mode` はおまかせのとき `"auto"` | スキーマ変更なし（String のまま）。マイグレーション不要 |

実行結果（2026-10-13）: iOS シミュレータ（iPhone 17, iOS 27）・macOS の両方でビルド警告なし、ユニットテスト・UI テストすべて通過。ホーム／クイズ／結果／進捗のライト・ダーク、macOS のホームを目視確認。実機での効果音・マナーモードの確認は未実施。

## H. v1.3 の判断（2026-10-13）

ユーザー要望: 「習得 100% は 600 点までを網羅した意味か」（→ 同梱 80 問の範囲でしかない、と回答）「もう少し段階的に学びたい」「問題を増やしたい」。段階の形は3案（スコア帯を順に進む / 小ユニットを順にクリア / 習得段階を細かく）から **スコア帯を順に進む** を、問題数は **単語400・文法200（Claude が書く）** をユーザーが選択。

| # | 判断 | 理由 |
|---|---|---|
| H1 | クリア条件は帯の習得率 80%（単語＋文法の合算） | 100% だと最後の数問の苦手で足止めされる。80% なら「おおむね身についた」で次へ進める。閾値は `Stage.clearRatio` 1か所 |
| H2 | 到達帯は単調増加（自動では下がらない）。「今の帯」だけ下の帯へ戻る | 開いた帯が閉じると気持ちが折れる。忘れた分は「今の帯」が戻ることで復習に回る |
| H3 | 設定のレベルトグル4つを廃止し、到達帯ピッカーに置き換え | 2つのレベル制御が併存すると「なぜこの問題が出ないか」が説明できない。手動で進める／戻す自由は残す |
| H4 | おまかせの係数: 今の帯 1 / 到達済み 0.35 / 未到達 0 | 復習を少し混ぜつつ、未到達の帯が漏れ出さないように。0.35 は「10 問中 2〜3 問が復習」程度の感覚値 |
| H5 | 問題データはスコア帯ごとに別の Claude サブエージェントが作成し、スクリプトで検証・結合 | 600 問を1本で書くより速く、帯ごとの難易度を指示しやすい。帯をまたぐ綴りの重複（54 語）が出たので、上の帯のものを差し替えて全体一意にした |
| H6 | 既存の 80 問は id・内容ともそのまま | 学習履歴は id に紐づくため（§2.1） |
| H7 | 言語モードを Swift 5 → Swift 6 に上げた | ユーザー指示。並行処理の問題が警告ではなくエラーで止まる方が安全。切り替えで出たエラーは `AIAssist` の static 定数 2 つが MainActor 既定分離のため `@Sendable` クロージャから触れなかったものだけで、`nonisolated` を付けて解消。他はすべてそのまま通った |
| H8 | アイコンは女神 Agenoria の胸像イラスト（ChatGPT 生成）を Icon Composer の 1 レイヤーで使う | 当初は「A + 若葉」の単一モチーフを提案したが、ユーザーが女神案を採用。ホーム画面サイズでも月桂冠と若葉が判別でき、名前の由来と直結する。背景除去の色フリンジはアイコンサイズでは見えない。未使用の旧レイヤーと空の `AppIcon.appiconset` は削除 |

未レビュー: 追加した 520 問の正解の一意性・自然さは人の目で見ていない。気になった問題はクイズ画面のブックマークで印を付けておけば、後でまとめて直せる。

## I. v1.4 の判断（2026-10-13）

ユーザー要望: 「起動時の画面に学習の選択肢が多くてごちゃごちゃしている」「ホームはダッシュボード的な扱いにしたい」。ウィジェットの構成（今の帯 / 今日と連続 / 2 週間 / 復習待ち・苦手）、主ボタンの下部固定、復習ボタンをウィジェット内に置くことはユーザーが選択。

| # | 判断 | 理由 |
|---|---|---|
| I1 | ホームは状態を見る画面にして、学習の選択肢を持たない | ユーザー要望。「何をやるか」はおまかせが決めるのが v1.2 以来の方針で、ホームに選択肢があるとそれと矛盾していた |
| I2 | 主操作「おまかせで10問」は下部固定バー（safeAreaInset） | 親指の届く位置に常にあり、ダッシュボードの長さに依らず埋もれない。クイズ画面の操作列と同じ作法で統一 |
| I3 | 分野・形式の選択は `分野を選ぶ` 画面（`Route.pick`）へそのまま移す | 選択 UI 自体は変えない。使う人には今までどおり、使わない人には見えない |
| I4 | 復習カードは復習待ち・苦手・間違えた・ブックマークがすべて 0 なら非表示 | 初回起動のホームを最小にする。1 セットやれば自然に現れる |
| I5 | 称号と全体の習得率はホームから進捗画面へ | ダッシュボードは「今の帯」に集中させる。演出要素は詳細側で十分 |
| I6 | 分野・形式の選択は永続化しない | 画面を開くたびに 単語 / ランダム。前回の選択を覚えると「なぜこの形式か」が分からなくなる。要望があれば AppSettings に 2 キー足すだけ |
| I7 | 14 日グラフは `DailyChart` として共通化 | ホームと進捗で同じ描画。進捗側は挙動不変 |
