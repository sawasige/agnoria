## C. Mac 対応で追加したもの（仕様外・最小）

- 選択肢に `1`〜`4` キー、`次へ` に Return、`×` に Esc のキーボードショートカット。
- ウィンドウ最小サイズ 480×640、既定 560×820。
- ツールバー配置は `.cancellationAction` / `.primaryAction` を使い、iOS では左上 `×`・右上ボタン群として表示。
- App Sandbox を有効化（通信なしなので追加の entitlement は不要）。
- 1ウィンドウのアプリなので macOS では `WindowGroup` ではなく `Window` シーン（File > New Window が付かない）。最後のウィンドウを閉じたら終了。Edit（取り消し・ペーストボード）、View > ツールバー、Help の既定メニュー項目は外す。

## G. v1.2 の判断（2026-10-13）

ユーザー要望: 「勉強する項目を選ぶのが面倒で、何を勉強すべきか判断できない。網羅的かつ苦手を自動で」「正誤で音を鳴らしたい」「UI がダサい」。

| # | 判断 | 理由 |
|---|---|---|
| G1 | おまかせは **単語・文法を1つのセットに混ぜる** | 「網羅的」の最短。片方ずつにすると結局ユーザーがどちらかを選ぶことになる。分野タイルは残したので従来どおりの出題も可能 |
| G2 | 優先度に **経過日数** を足した（卒業 0.3→1.5、学習中 1→1.5、14日で上限） | 旧ロジックは卒業した問題がほぼ出なくなり、忘れても戻ってこない。間隔反復の簡易版。未回答・間違いは時間に依存しない |
| G3 | 習得段階は Priority の判定をそのまま4段階にしただけ | 可視化のために別の指標を増やすと、出題ロジックと画面の数字がずれる |
| G4 | `間違えた問題` / `ブックマーク` は **単語・文法の合算** | おまかせと同じ思想。v1.1 の「選択中セグメントのもの」から変更 |
| G5 | 効果音は **合成音**（Python の wave で生成し afconvert で CAF 化） | ライセンス不明の音源を持ち込まない。最初のやわらかいチャイムは不評で、3案（クイズ番組風 / ゲーム風 / 控えめ）を聞き比べて **クイズ番組風（ピンポーン / ブッブー）** に決定（2026-10-13）。差し替えは同名の CAF を置くだけ |
| G6 | 効果音の後に自動読み上げを **0.45 秒遅らせる** | 効果音と読み上げがかぶると両方聞き取れない。v1.1 で懸念していた「読み上げが早すぎる」も同時に解消 |
| G7 | UI は **Liquid Glass ネイティブ**（ユーザー選択。他案: ダーク固定 / フラット・ポップ） | OS 標準のスタイルなので手描きの装飾が最小で済み、ライト／ダーク両対応が自動。Xcode 既定から外れるビルド設定も不要 |
| G8 | 進捗画面は閲覧のみ。操作はホームに集約 | 「何をやるか」はおまかせボタン1つにしたいので、進捗画面から出題を始められるようにしない |
| G9 | `StudySession.mode` はおまかせのとき `"auto"` | スキーマ変更なし（String のまま）。マイグレーション不要 |

実行結果（2026-10-13）: iOS シミュレータ（iPhone 17, iOS 27）・macOS の両方でビルド警告なし、ユニットテスト・UI テストすべて通過。ホーム／クイズ／結果／進捗のライト・ダーク、macOS のホームを目視確認。実機での効果音・マナーモードの確認は未実施。

| H3 | 設定のレベルトグル4つを廃止し、到達帯ピッカーに置き換え | 2つのレベル制御が併存すると「なぜこの問題が出ないか」が説明できない。手動で進める／戻す自由は残す |

## I. v1.4 の判断（2026-10-13）

ユーザー要望: 「起動時の画面に学習の選択肢が多くてごちゃごちゃしている」「ホームはダッシュボード的な扱いにしたい」。ウィジェットの構成（今の帯 / 今日と連続 / 2 週間 / 復習待ち・苦手）、主ボタンの下部固定、復習ボタンをウィジェット内に置くことはユーザーが選択。

| # | 判断 | 理由 |
|---|---|---|
| I1 | ホームは状態を見る画面にして、学習の選択肢を持たない | ユーザー要望。「何をやるか」はおまかせが決めるのが v1.2 以来の方針で、ホームに選択肢があるとそれと矛盾していた |
| I2 | 主操作「おまかせで10問」は下部固定バー（safeAreaInset） | 親指の届く位置に常にあり、ダッシュボードの長さに依らず埋もれない。クイズ画面の操作列と同じ作法で統一 |
| I3 | 分野・形式の選択は `分野を選ぶ` 画面（`Route.pick`）へそのまま移す | 選択 UI 自体は変えない。使う人には今までどおり、使わない人には見えない |
| I4 | 復習カードは復習待ち・苦手・間違えた・ブックマークがすべて 0 なら非表示 | 初回起動のホームを最小にする。1 セットやれば自然に現れる |
| I5 | 称号と全体の習得率はホームから進捗画面へ | ダッシュボードは「今の帯」に集中させる。演出要素は詳細側で十分 |
| I6 | 分野・形式の選択は永続化しない | 画面を開くたびに 単語 / ランダム。前回の選択を覚えると「なぜこの形式か」が分からなくなる。要望があれば AppSettings に 2 キー足すだけ |
| I7 | 14 日グラフは `DailyChart` として共通化 | ホームと進捗で同じ描画。進捗側は挙動不変 |
| I8 | 女神 Agenoria の立ち絵を結果画面（表情 4 種）とホームのヘッダー（アイコンと同じ絵）に置く | ユーザー要望。4 コマ画像はアルファなし（市松が焼き込み）だったので、外周から連結する白〜薄灰だけを透明化する Swift スクリプトで切り出した（目や歯の白は残る）。表情の閾値は結果メッセージと同じにして、文言と顔が食い違わないようにする |
| I9 | 効果音と AVAudioSession の設定を actor に移し、メインスレッドから外す | Xcode の実行時診断「AVAudioSession Hang Risk」（setActive の同期呼び出し）への対応。非同期 `activate(options:)` だけでは AVAudioPlayer 側の暗黙の有効化が残るため、プレイヤーごと actor に閉じ込めた。`log show` の `com.apple.runtime-issues` で旧 5 件 → 0 件 |
| I10 | 一度習得した問題は、復習で間違えても次の正解で習得に戻す（`masteredAt`） | 「100% まで何セット？」の問いに対し、実ロジックで 1500 セットのシミュレーションをしたところ、正答率 96% の学習者でも 97〜99% で頭打ちになり一度も 600/600 に届かなかった。原因は復習の 1 ミスで 3 連続正解を取り直させる判定の厳しさ。初見の判定は変えず、習得後だけ緩める。optional プロパティの追加なので SwiftData の軽量マイグレーションで済み、履歴は残る（Mac の既存ストアで確認）。変更後の同じシミュレーション: 頭打ちが 98.5〜99.8% に上がり、正答率 92% 以上の学習者は 500〜700 セットで 600/600 に届くようになった。帯が開くまでのセット数は変わらない |
