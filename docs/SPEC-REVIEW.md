ユーザー要望: 「勉強する項目を選ぶのが面倒で、何を勉強すべきか判断できない。網羅的かつ苦手を自動で」「正誤で音を鳴らしたい」「UI がダサい」。

| # | 判断 | 理由 |

| G1 | おまかせは **単語・文法を1つのセットに混ぜる** | 「網羅的」の最短。片方ずつにすると結局ユーザーがどちらかを選ぶことになる。分野タイルは残したので従来どおりの出題も可能 |
| G2 | 優先度に **経過日数** を足した（卒業 0.3→1.5、学習中 1→1.5、14日で上限） | 旧ロジックは卒業した問題がほぼ出なくなり、忘れても戻ってこない。間隔反復の簡易版。未回答・間違いは時間に依存しない |
| G3 | 習得段階は Priority の判定をそのまま4段階にしただけ | 可視化のために別の指標を増やすと、出題ロジックと画面の数字がずれる |
| G4 | `間違えた問題` / `ブックマーク` は **単語・文法の合算** | おまかせと同じ思想。v1.1 の「選択中セグメントのもの」から変更 |

## H. v1.3 の判断（2026-10-13）

ユーザー要望: 「習得 100% は 600 点までを網羅した意味か」（→ 同梱 80 問の範囲でしかない、と回答）「もう少し段階的に学びたい」「問題を増やしたい」。段階の形は3案（スコア帯を順に進む / 小ユニットを順にクリア / 習得段階を細かく）から **スコア帯を順に進む** を、問題数は **単語400・文法200（Claude が書く）** をユーザーが選択。

| # | 判断 | 理由 |
|---|---|---|
| H1 | クリア条件は帯の習得率 80%（単語＋文法の合算） | 100% だと最後の数問の苦手で足止めされる。80% なら「おおむね身についた」で次へ進める。閾値は `Stage.clearRatio` 1か所 |
| H2 | 到達帯は単調増加（自動では下がらない）。「今の帯」だけ下の帯へ戻る | 開いた帯が閉じると気持ちが折れる。忘れた分は「今の帯」が戻ることで復習に回る |
| H3 | 設定のレベルトグル4つを廃止し、到達帯ピッカーに置き換え | 2つのレベル制御が併存すると「なぜこの問題が出ないか」が説明できない。手動で進める／戻す自由は残す |
| H4 | おまかせの係数: 今の帯 1 / 到達済み 0.35 / 未到達 0 | 復習を少し混ぜつつ、未到達の帯が漏れ出さないように。0.35 は「10 問中 2〜3 問が復習」程度の感覚値 |
| H5 | 問題データはスコア帯ごとに別の Claude サブエージェントが作成し、スクリプトで検証・結合 | 600 問を1本で書くより速く、帯ごとの難易度を指示しやすい。帯をまたぐ綴りの重複（54 語）が出たので、上の帯のものを差し替えて全体一意にした |
| H6 | 既存の 80 問は id・内容ともそのまま | 学習履歴は id に紐づくため（§2.1） |
| H7 | 言語モードを Swift 5 → Swift 6 に上げた | ユーザー指示。並行処理の問題が警告ではなくエラーで止まる方が安全。切り替えで出たエラーは `AIAssist` の static 定数 2 つが MainActor 既定分離のため `@Sendable` クロージャから触れなかったものだけで、`nonisolated` を付けて解消。他はすべてそのまま通った |
| H8 | アイコンは女神 Agenoria の胸像イラスト（ChatGPT 生成）を Icon Composer の 1 レイヤーで使う | 当初は「A + 若葉」の単一モチーフを提案したが、ユーザーが女神案を採用。ホーム画面サイズでも月桂冠と若葉が判別でき、名前の由来と直結する。背景除去の色フリンジはアイコンサイズでは見えない。未使用の旧レイヤーと空の `AppIcon.appiconset` は削除 |

レビュー済み（2026-10-14）: 600 問をカテゴリごとに読み直した。正解の誤りはゼロ、解説の誤りは pos-105 の 1 件（responsibility が for と結びつかないという誤った説明）。直したのは次の 4 種類。
- 意味の衝突: 同じ訳語を持つ語（会議 / 簡潔な / 簡潔に / 要約 / 勤勉な / 助言する / 連続した / 上司 / 雇う など）は「英語で言うと」で正解が 2 つになり得るので、片方の訳語を具体化した（例: conference → 大規模な会議・協議会、brief → 手短な、recap → おさらい）。アプリは同じ訳語の語を誤答に出さない仕組みだが、学習者が区別できる訳語にする方が良い
- 訳語のずれ: prospective（見込みのある → 将来の・見込みの）、accrue（積み立てられる → たまる）、stipend（手当 → 給付金）、eligible（資格のある → 対象となる）など。distractor が正解にもなり得たもの（store の 倉庫、extend の 拡大する、assure の 確実にする）を差し替え
- 例文: bring / take、revenue / profit、meeting の weekly meeting など、空欄に他の語も入る例文を手がかりのある文に書き換え。excess は形容詞的に使っていたので名詞用法に
- 文法: ほぼ同じ文の重複（vocab-203/208/302、pron-204/206、pos-202/205/206/408、tense-003/202/208/302/309/405）を別の文に書き換え、600 帯で下の帯と同じ論点だった prep-006/401/404/406 と tense-006 を難しい問題に差し替え、時制でない論点（tense-105 主語の一致、tense-406 仮定法）を時制・態の問題にした。one another（pron-409）は each other を正解にして両者が同じ意味だと解説に書いた
- 波ダッシュは全体を「〜」(U+301C) に統一
id はすべて据え置き（学習履歴の紐づけは変えない）。

## I. v1.4 の判断（2026-10-13）

ユーザー要望: 「起動時の画面に学習の選択肢が多くてごちゃごちゃしている」「ホームはダッシュボード的な扱いにしたい」。ウィジェットの構成（今の帯 / 今日と連続 / 2 週間 / 復習待ち・苦手）、主ボタンの下部固定、復習ボタンをウィジェット内に置くことはユーザーが選択。

| # | 判断 | 理由 |
|---|---|---|
| I1 | ホームは状態を見る画面にして、学習の選択肢を持たない | ユーザー要望。「何をやるか」はおまかせが決めるのが v1.2 以来の方針で、ホームに選択肢があるとそれと矛盾していた |
| I2 | 主操作「おまかせで10問」は下部固定バー（safeAreaInset） | 親指の届く位置に常にあり、ダッシュボードの長さに依らず埋もれない。クイズ画面の操作列と同じ作法で統一 |
| I3 | 分野・形式の選択は `分野を選ぶ` 画面（`Route.pick`）へそのまま移す | 選択 UI 自体は変えない。使う人には今までどおり、使わない人には見えない |
| I4 | 復習カードは復習待ち・苦手・間違えた・ブックマークがすべて 0 なら非表示 | 初回起動のホームを最小にする。1 セットやれば自然に現れる |
| I5 | 称号と全体の習得率はホームから進捗画面へ | ダッシュボードは「今の帯」に集中させる。演出要素は詳細側で十分 |
| I6 | 分野・形式の選択は永続化しない | 画面を開くたびに 単語 / ランダム。前回の選択を覚えると「なぜこの形式か」が分からなくなる。要望があれば AppSettings に 2 キー足すだけ |
| I7 | 14 日グラフは `DailyChart` として共通化 | ホームと進捗で同じ描画。進捗側は挙動不変 |
| I8 | 女神 Agenoria の立ち絵を結果画面（表情 4 種）とホームのヘッダー（アイコンと同じ絵）に置く | ユーザー要望。4 コマ画像はアルファなし（市松が焼き込み）だったので、外周から連結する白〜薄灰だけを透明化する Swift スクリプトで切り出した（目や歯の白は残る）。表情の閾値は結果メッセージと同じにして、文言と顔が食い違わないようにする |
